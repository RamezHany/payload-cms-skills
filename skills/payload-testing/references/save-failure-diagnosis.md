# Save-failure diagnosis

Use the first row whose symptom matches. Run the confirmation before editing code. A fix that skips the confirmation usually treats the wrong layer.

| Symptom | Likely cause | How to confirm | Fix |
| --- | --- | --- | --- |
| Save spins forever, or the server logs `SQLITE_BUSY` / `database is locked` | `transactionOptions` is set on `sqliteAdapter`, a hook holds a transaction open, or two processes share one SQLite file (dev server and tests) | Search `src/payload.config.ts` for `transactionOptions`. Compare `DATABASE_URL` in the dev server and the test process. Payload's SQLite docs say transactions default to off and should stay off because they lock the file. | Remove `transactionOptions`. Leave transactions disabled. Give Vitest and Playwright separate `.data/*.db` files, and stop the other dev server before e2e. |
| Save works locally and fails after deploy with "no such table", a missing column, or a Drizzle schema error | Production has push disabled (development only) and the migration was never created or never ran | Read the Vercel build log. The `ci` script must run `payload migrate` before `next build`. Open `src/migrations` and confirm a migration exists for the latest schema change. | Create and commit a migration, then redeploy with the build command `pnpm run ci`. See the `payload-deploy-vercel` skill. Do not turn push on in production. |
| Save works locally and returns 403 in production, often with a CSRF message | `serverURL`, `csrf`, or `cors` does not include the origin the browser sends | In the failing request, compare the `Origin` header with the `csrf` array in `src/payload.config.ts`. A preview URL or a custom domain that is missing from the array fails this way while `http://localhost:3000` works. | Set `serverURL`, `csrf`, and `cors` to that origin. The `payload-auth-rbac` skill shows the config. Include the production origin and the origin of the deployment you are actually using. |
| Upload returns 413 or "Request Entity Too Large" on Vercel, and the same file uploads locally | The file went through a function body. Vercel rejects request bodies over 4.5 MB (`FUNCTION_PAYLOAD_TOO_LARGE`). Verify at https://vercel.com/docs/functions/limitations | The failing request URL is a Payload API route, not the storage host. The file is larger than 4.5 MB. | Enable `clientUploads: true` as in the `payload-media` skill. Do not raise a body limit; the platform limit is fixed. |
| Browser console shows a CORS error on a direct upload, often mentioning `PUT` or `If-None-Match` | The bucket CORS policy does not allow the admin origin, the `PUT` method, or that header | The preflight to the storage host fails. Compare it with the CORS JSON in the `payload-media` skill's R2 reference. | Add the admin origin, `GET` and `PUT`, and headers `Content-Type` and `If-None-Match`. |
| The admin says the save succeeded, but the public page still shows the old value | The document is still a draft, or the publish hook revalidated a path the page does not use | Check `_status` in the admin. Read the server log for the `revalidate (` line from the `payload-performance` skill. Compare those paths with the browser URL, including the locale prefix. | Publish the document. Fix the collection's targets so they list the real routes. A draft save must log nothing. |
| Every page regenerates after an ordinary save, or the Vercel ISR write graph jumps on each save | A shared tag such as `cms-content` is on every query, or a hook calls `revalidatePath(path, 'layout')` for a collection that is not a layout global | Search the repo for `cms-content`, `revalidateTag(`, and `revalidatePath(`. Read the `revalidate (` log line. One content save must not list every route. | Follow the `payload-performance` skill. Remove the shared tag. Restrict `'layout'` to layout-global hooks. Re-run the invalidation trace spec. |
| Live preview iframe is blank and the console says the frame was refused | `Content-Security-Policy` has `frame-ancestors 'none'`, or `X-Frame-Options` is `DENY` | `curl.exe -sI` the page URL and read those headers. Also confirm `serverURL` matches the origin in the address bar. | Use `frame-ancestors 'self'` and do not send `X-Frame-Options: DENY`. The `payload-live-preview` skill and the `payload-deploy-vercel` skill own this header. |
| "The following field is invalid: slug" or a unique-constraint error from SQLite | Another document, including a draft, already has that slug. Slugs are not localized unless the project asked for translated URLs, so the other locale can collide too. | Search the collection for the slug, drafts included. | Change the slug. Do not drop the unique index. Do not localize `slug` to escape the error unless the `payload-localization` skill's rule for translated URLs applies. |
| The editor saved Arabic (or the other locale) but the public page in that locale still shows the default language | The admin content locale was not the locale they typed into, so the value landed in the other locale's row | Look at the locale control in the document header before assuming the field is empty. Query with `locale` set to each code and compare. | Use the locale sync from the `payload-localization` skill. Pass `locale` to every frontend `payload.find`. |
| Autosave replaced text the editor had just typed, or a published page flashed back to an older sentence | Two sessions had the document open, or a slow autosave response (interval is 100 ms for live preview) wrote an older draft over the newer one | Open the versions list for the document and compare the last two draft timestamps. | Restore the version the editor wanted. Do not turn off autosave while live preview depends on it. Avoid two people editing the same document at once. |
| A seed script, migration, or `payload run` script throws `Invariant: static generation store missing` (or any throw inside `revalidatePath` / `revalidateTag`) | A hook called Next cache functions outside a Next.js request | The stack includes `revalidatePath` or `revalidateTag` and the command was not `pnpm dev` or a route. | Pass `context: { disableRevalidate: true }` on every Local API call in that script. The `payload-performance` skill requires hooks to return immediately when that flag is set. |
| The admin compiles, but a custom component renders as an empty region or "Component not found" | The import map was not regenerated after the component was added | Search `src/app/(payload)/admin/importMap.js` for the component path. | Run `pnpm generate:importmap` and commit the updated map. The admin path in the collection config must be `@/components/...#ExportName`. |

## After the fix

Re-run the smallest spec that covers the symptom (`pnpm test:int` or the single Playwright file). A save fix is not done because the spinner stopped once.
